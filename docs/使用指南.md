# 使用指南

本指南对应当前仓库的 `gui.py`、`ZjuRun.exe` 和配置格式。建议先完成单机准备，再尝试双机；两台设备需分别完成信任、开发者模式和 DDI 准备。

[返回 README](../README.md)

## 选择运行方式

| 方式 | 适用系统 | 需要安装 Python | 启动入口 |
| --- | --- | --- | --- |
| 已打包 EXE | Windows | EXE 本身不需要；源码 DDI 准备命令需要 | `ZjuRun.exe` |
| 源码 GUI | Windows | Python 3.11 | `.\.venv\Scripts\python.exe gui.py` |
| 源码 GUI | macOS | Python 3.11，且需支持 Tkinter | `sudo ./.venv/bin/python gui.py` |

`main.py` 是旧命令行入口，目前未适配新的异步隧道接口，请使用 GUI。仓库 EXE 不能在 macOS 上运行。macOS 是原项目记录的运行平台，本次文档更新未在 macOS 或真机上复测。

## 设备准备

1. **Windows 驱动。** 按项目原有方式安装 iTunes。先确认 iTunes 能识别设备；不能识别时优先排查驱动、USB 数据线和接口。
2. **连接与信任。** 使用能传输数据的 USB 线，解锁设备，出现“信任此电脑”提示时完成信任。程序只统计 USB 设备，Wi-Fi 连接不计入 GUI 的设备数量。
3. **开启开发者模式。** 进入“设置 → 隐私与安全性 → 开发者模式”，按提示重启，重启后解锁、确认开启。参见 [Apple 官方说明](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)。
4. **找不到开发者模式时。** 程序检测到模式关闭时会尝试让该选项显示，然后退出本次运行。按日志完成设备设置后再次启动运行；失败时保留日志排查。
5. **准备 DDI。** 按下文挂载步骤操作。GUI 环境检查只检查权限、设备数量、系统版本和开发者模式，没有自动执行 DDI 挂载。
6. **匹配数量。** 单机只连接 1 台设备，双机恰好连接 2 台设备。运行期间保持连接。

代码拒绝 iOS 17 以下系统。原项目测试记录是 iOS 18.3.1；版本检查通过不代表该版本的所有设备服务都兼容。

## Windows EXE

下载整个项目并解压，或复制以下文件到同一可写目录：

```text
ZjuRun.exe
config.yaml
ZJGroute.txt
YQroute.txt
HNroute.txt
CUFEroute.txt
```

至少保留 `config.yaml` 和它所指定的路线文件。不要在压缩包内直接启动，也不要只复制 EXE 而遗漏配置。

右键 `ZjuRun.exe` → “以管理员身份运行”。普通权限可能能打开界面，但开始运行时会被环境检查拒绝。EXE 从自身目录读取配置和相对路线，无需将终端工作目录切换到 EXE 目录；GUI 保存设置时会写入这里的配置文件。

## Windows 源码 GUI

安装 Python 3.11 后，在 PowerShell 中执行：

```powershell
git clone https://github.com/Nothing-cell-bit/iOSRealRun-cli-18.git
cd iOSRealRun-cli-18
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

已有项目时直接进入目录，不必重复克隆。这里使用虚拟环境解释器，无需运行 `Activate.ps1`。

以管理员身份重新打开 PowerShell，进入项目目录：

```powershell
.\.venv\Scripts\python.exe gui.py
```

依赖清单见 [requirements.txt](../requirements.txt)。排查兼容问题时先记录实际版本，不要直接把所有依赖升级到最新版。

## macOS 源码 GUI

准备 Python 3.11，在终端执行：

```bash
git clone https://github.com/Nothing-cell-bit/iOSRealRun-cli-18.git
cd iOSRealRun-cli-18
python3.11 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python -m tkinter
```

最后一条命令确认 Python 能打开 Tkinter 测试窗口。若缺少 `_tkinter`，先为该 Python 安装提供 Tk 支持的发行版或对应组件。

关闭测试窗口，完成设备准备后，在项目目录启动：

```bash
sudo ./.venv/bin/python gui.py
```

使用同一虚拟环境，避免另一个 `sudo python3` 找不到依赖。`pywin32` 带有 Windows 平台条件，不会在 macOS 安装。

## DDI 挂载

DDI 是设备开发服务使用的磁盘镜像。当前 GUI 不负责自动挂载。首次准备或定位服务连接失败时，先检查挂载；原项目文档也包含此步骤。

Windows 在项目目录、管理员 PowerShell 中执行：

```powershell
.\.venv\Scripts\python.exe -m pymobiledevice3 usbmux list --usb
.\.venv\Scripts\python.exe -m pymobiledevice3 mounter auto-mount
```

macOS 在项目目录执行：

```bash
./.venv/bin/python -m pymobiledevice3 usbmux list --usb
sudo ./.venv/bin/python -m pymobiledevice3 mounter auto-mount
```

双机可每次只连接一台完成挂载，再接回两台运行；也可以指定 `usbmux list --usb` 中对应的设备标识：

```powershell
.\.venv\Scripts\python.exe -m pymobiledevice3 mounter auto-mount --udid "设备的UDID"
```

设备重启后，若开发服务无法连接，再检查挂载状态。自动挂载可能需要联网获取镜像资源，按命令输出判断结果。

**当前已知依赖问题：** 文档更新时，本地 Python 3.11.9 环境中的 `pymobiledevice3==4.10.0` 搭配 `ipsw-parser==1.7.5`，执行 `mounter auto-mount --help` 即报错：

```text
ModuleNotFoundError: No module named 'ipsw_parser.img4'
```

此时命令尚未进入设备挂载阶段，不能当成挂载成功。当前仓库未提供已验证的依赖修复版本组合。出现同样错误时，保留完整堆栈和以下版本信息，先解决兼容问题再继续；GUI 能打开不能代替 DDI 检查。

```powershell
.\.venv\Scripts\python.exe -m pip show pymobiledevice3 ipsw-parser
.\.venv\Scripts\python.exe -m pip check
```

仓库根目录 EXE 的 `--pmd3 mounter auto-mount --help` 也复现了同一错误，不能用它绕过此依赖问题。EXE 启动检查不代表全部 `pymobiledevice3` 子命令可用。准备 DDI 时使用能看到完整输出的终端环境，并确认依赖问题已经解决。

## 图形界面操作

1. **选择模式。** 默认“双机运行”。一台设备切换“单机运行”；双机要求恰好 2 台 USB 设备。
2. **检查数量。** 数量约每 1.5 秒刷新，点击开始时再次检查；数量不符会记录日志并拒绝启动。
3. **选择路线。** 下拉框扫描配置目录中的 `*route.txt`。默认配置是 `ZJGroute.txt`；新增文件后重启界面。
4. **设置速度。** 单位为米/秒，输入有限且大于 0 的数字。按回车或离开输入框保存。代码未完整校验范围，避免 0、负数、`nan`、`inf`。
5. **开始运行。** 成功日志包括“环境检查通过”“隧道建立成功”“成功加载路线”及“开始单机跑步”或“开始双机同步跑步”。仅看到界面或设备数量不代表已模拟。
6. **观察运行。** 路线循环，每圈速度和路径有小幅随机变化；双机共用同一圈轨迹。完成一圈输出“跑完一圈了”，不会按指定距离自动停止。
7. **停止。** 点击“停止运行”，等日志显示“已停止”、按钮恢复“开始运行”，再关闭窗口或拔线。

运行中不能修改模式、速度和路线。关闭运行中的窗口会询问是否退出，并发起停止流程。“已停止”表示程序结束停止流程，仍需在设备端检查实际定位；清理失败可能未记录为错误。

## 配置文件

```yaml
v: 4.2
routeConfig: ZJGroute.txt
libimobiledeviceDir: libimobiledevice
imageDir: DeveloperDiskImage
```

| 配置项 | 含义 |
| --- | --- |
| `v` | 速度，单位 `m/s`，使用大于 0 的有限数值 |
| `routeConfig` | 路线文件名或路径；相对路径以配置目录为基准，也支持绝对路径 |
| `libimobiledeviceDir` | 历史字段，当前 GUI 连接流程未使用；保留以兼容配置保存 |
| `imageDir` | 历史字段，当前 GUI 不通过它挂载 DDI；保留以兼容配置保存 |

源码从 `config.py` 所在目录读取配置，EXE 从自身目录读取。使用 UTF-8 和空格缩进。手工修改后重启；GUI 在启动时读取一次，在设置变化或开始时保存。

模式不写入 YAML，重启仍默认双机。GUI 保存时仅保留上表四个字段，不要依赖额外字段长期保存在该文件中。

配速换算：`每公里用时（秒） = 1000 / 速度（m/s）`。`4.2 m/s` 约为 `3 分 58 秒 / 公里`；实际每圈有随机变化。

## 自定义路线

命名为 `Myroute.txt`，放在 `config.yaml` 同目录。内容是逗号分隔的坐标对象，**最外层不要加方括号**：

```text
{"lng": "120.08970", "lat": "30.31196"},
{"lng": "120.08953", "lat": "30.31191"},
{"lng": "120.08944", "lat": "30.31181"}
```

这是格式示例，请根据自己的路线采集坐标，保存为 UTF-8：

- `lng` 是经度、`lat` 是纬度，值可以是数字或可转换成数字的字符串。
- 至少两个不同点，按行进顺序排列；最后一点会接回第一点形成循环。
- 当前逻辑将输入当作 **百度 BD-09 坐标**，再转换为设备使用的 WGS-84。直接混用高德 GCJ-02 或 WGS-84 会偏移。
- GUI 只在启动时扫描以 `route.txt` 结尾的文件。保存后重启，选择 `Myroute.txt`。

`routeConfig` 支持绝对路径，但路径不在扫描目录时不会自动成为下拉候选。初次配置建议放在配置同目录并使用文件名。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 设备数为 0 | 解锁、信任、更换数据线或接口；Windows 确认 iTunes 能识别，再运行 `usbmux list --usb` |
| 要求恰好连接 2 台设备 | 默认双机；只有一台时切换单机，两台时确认都通过 USB 连接 |
| 管理员 / root 权限不足 | Windows 以管理员身份运行 EXE 或 PowerShell；macOS 用 `sudo ./.venv/bin/python gui.py` |
| 未开启开发者模式 | 完成设置、重启和开启确认后再运行；双机分别设置 |
| 隧道或定位服务连接失败 | 先停止，确认 USB、信任、开发者模式和 DDI，检查对应设备日志后重试 |
| 缺少 `ipsw_parser.img4` | 挂载命令依赖兼容问题，按 DDI 一节记录版本和堆栈；不要假定镜像已挂载 |
| 找不到配置或路线 | EXE 检查自身目录；源码检查 `config.py` 同目录及 `routeConfig` 指定路径 |
| 设置无法保存 | 检查目录和配置是否可写，将完整项目移到可写目录 |
| 新路线不在下拉框 | 文件名以 `route.txt` 结尾，放在配置同目录，重启 GUI |
| 路线解析错误 / 位置偏移 | 检查格式、至少两个不同点、经纬度字段及 BD-09 坐标系 |
| 打包报 `PackageNotFoundError: readchar` | 用仓库 `ZjuRun.spec` 和 `build_exe.ps1` 重打包，包含版本元数据 |
| `main.py` 报协程或解包错误 | 旧入口未适配，改用 `gui.py` 或 EXE |
| 停止后定位未恢复 | 确认停止完成；仍异常时重启设备，再检查地图中的实际位置 |

Windows 可检查 Apple Mobile Device Service 的本地监听端口。端口连通不代表设备已配对或定位服务可用：

```powershell
.\.venv\Scripts\python.exe check_usbmux.py
```

反馈时附电脑系统、设备系统、运行模式、EXE/源码方式、完整错误和依赖版本；公开日志前遮盖设备 UDID 等设备标识。

## 测试与打包

以下命令在 Windows 项目目录执行，无需连接设备。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前 6 项测试覆盖 EXE 旁配置读取/保存、从其他工作目录加载路线、绝对路线路径及两种环境下的隧道命令。测试会暂存并恢复仓库配置，不要与正在运行的程序同时执行。

打包：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\build_exe.ps1
```

`dist/` 中生成 EXE 并复制当前配置和所有 `*route.txt`。分发时一起提供；构建不会自动替换仓库根目录 EXE。

检查新 EXE 的 GUI 启动和内置隧道 CLI 帮助：

```powershell
.\.venv\Scripts\python.exe tests/smoke_exe.py dist\ZjuRun.exe
```

检查会短暂打开 GUI 后关闭，并验证 `--pmd3 lockdown start-tunnel --help` 输出；不连接设备、不开始定位模拟。它不验证 DDI 挂载，也不替代真机单机/双机和定位恢复检查。
